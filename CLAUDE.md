# Billiard Bot — инструкция для Claude

## Что это за проект
Telegram-бот `@billiardinho` для записи партий в бильярд между двумя игроками.
Стек: Node.js (ESM), better-sqlite3, node-telegram-bot-api.

## Структура
```
billiard-bot/
├── src/
│   ├── bot.js        — основная логика, FSM, обработка команд и кнопок
│   ├── db.js         — SQLite: пары игроков и сессии
│   ├── formatter.js  — форматирование статистики для вывода
│   └── fsm.js        — машина состояний (in-memory, per chatId)
├── import.js         — одноразовый импорт исторических данных из Excel
├── fix.js            — утилита для диагностики БД
├── Dockerfile
├── docker-compose.yml
└── package.json
```

## База данных (SQLite)
Две таблицы:

**pairs** — пары игроков:
- `uid1` — числовой Telegram ID игрока 1 (создатель пары)
- `uid2` — числовой Telegram ID игрока 2 (заполняется когда партнёр присоединяется)
- `username2` — @username игрока 2 (для матчинга при /start)
- `name1`, `name2` — отображаемые имена

**sessions** — партии:
- `pair_id` — ссылка на пару
- `score1` — победы uid1, `score2` — победы uid2
- `played_at` — ISO timestamp

## Деплой
- Платформа: **Railway** (проект `brave-encouragement`, сервис `billiardinho`)
- База данных: Railway Volume примонтирован в `/app/data`
- Переменная окружения: `DB_PATH=/app/data/billiard.db`, `BOT_TOKEN=...`
- Запуск через **Dockerfile** (не через npm start!)
- Текущий CMD в Dockerfile: `CMD ["sh", "-c", "node import.js && node src/bot.js"]`

## Как работает пользовательский флоу
1. Первый игрок пишет /start → бот берёт имя из Telegram профиля → просит @username партнёра
2. Партнёр пишет /start → бот матчит по username → просит подтвердить имя → пара готова
3. Запись счёта — через кнопку "🎱 Записать счёт" → два шага: сколько выиграл я, сколько соперник
4. Статистика — кнопки меню: за всё время, за месяц, за период (3w / 2m / даты)

## Важные детали
- `railway run` выполняет код ЛОКАЛЬНО, а не на сервере — не использовать для запуска скриптов на Railway
- FSM состояния хранятся в памяти (Map) — сбрасываются при рестарте бота
- import.js безопасен для повторного запуска — пропускает дубликаты по дате
- Игроки могут вводить счёт независимо друг от друга, данные общие
